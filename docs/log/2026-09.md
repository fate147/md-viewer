## 2026-09-30 · 打包形态改为 onedir（修 D 盘 onefile 无法启动）

- **背景**：交付后用户双击根目录 md-viewer.exe 报 could not create temporary directory，每次必现。排查发现：不是项目代码问题（hello.py 打的 6.9MB 空 exe 放 C 盘能跑、复制到 D 盘即失败）；不是 PyInstaller 版本问题（6.14.2/6.21.0/6.22.3 全失败，且 6.14.2 无 SDDL 逻辑仍失败）；不是临时目录位置问题（--runtime-tmpdir 指向已存在 C 盘目录仍失败）；不是权限问题（ctypes 调同参数 CreateDirectoryW 在 D 盘成功，SID 与 SDDL 完全一致）。已排除磁盘空间、Defender、UAC manifest、盘符文件系统。疑似 D 盘第三方文件系统过滤驱动，fltmc 需管理员权限无法确认。已知矛盾：用户 9-11 的旧 onefile exe 在 D 盘能跑，说明环境此后变化，旧 exe 已丢失无法对比。
- **处理**：md-viewer.spec 改 onedir（EXE exclude_binaries + COLLECT），显式 upx=False；spec 顶部写入完整排除清单，避免以后重犯。register.bat 路径改为 md-viewer\md-viewer.exe；.md 关联由 registry.py 取 sys.executable 自动适配，无需改代码。交付 dist\md-viewer 整个文件夹到根目录（md-viewer\md-viewer.exe + _internal\，75MB）。验证：双击启动窗口标题 'MD Viewer - 未命名'、带文件参数 'MD Viewer - AGENTS.md'、内存 50.8MB、无 crash log。顺带把 hook 迁到 .githooks/（受版本控制）并修掉只差时间戳就产生假 commit 的问题。
- **指针**：docs/decisions/tech-choices.md TC-006、md-viewer.spec、AGENTS.md 铁律

## 2026-09-30 · 预览性能优化：渐进渲染 + HTML 缓存 + 全文缓存

- **背景**：用户反馈打开内容多的 MD 文档卡顿。先做实测定位而非猜：对 22K body 的真实文档分段计时，发现 load_html 的 parse 只占 12ms，95%(231ms) 是 tkhtml 排版；且排版随注入体积近似线性增长，节流防抖与 markdown 提速都无效。进一步验证 split 注入：单次 243ms vs 首块 42ms。旧的 500ms 冷却机制早在 c03842e 就被删了，AGENTS.md 描述已与代码脱节。
- **处理**：① core/markdown_render 新增 split_html(html, parts)：按顶层块级闭合标签切块，最后一段复用原文档保证与一次性渲染逐字节一致（实测 17 组样本 + tkhtml 实际解析均通过）② ui/preview 重写：HTML≥30K 走渐进渲染（1/4 首屏→120ms 后补全文）、每标签 HTML 缓存（键为 id(tab)+(len,hash,theme_id)，上限 4 条）、worker 改单飞（一个在途+一份待发+代数预检）③ ui/editor 新增 _text_cache/_stats_cache：同一次打开原文取 4~5 次全文降为 0 次，编辑时经 <<Modified>> 失效。实测：97KB 文档打开同步工作 46ms、TTFP 342ms（原 1582ms，4.6x）；5 次连发请求只产生 2 次渲染。顺带修 bugs/004（关最后一个标签后预览空白）。
- **指针**：docs/features/preview.md、docs/features/editor.md、docs/bugs/004-*.md、docs/architecture.md
