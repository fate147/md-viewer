## 0. 一页结论

MD Viewer 的动效基线是克制的，问题不是“动画太多”，而是**动效只活在悬停层**：全项目 5 条 `transition`、2 个 `@keyframes`、2 个 `animation`、0 个 `infinite`。真正的“切换面”——F2 双态、目录开关、标签条首次出现、主题切换——全部是 0ms 硬切；而规格点名的 `prefers-reduced-motion` 只关了 `transition`，没关 `animation`，所以命令面板在“减少动效”模式下仍然会淡入和弹跳。

- 5 条过渡全是悬停/选中：TOC 项、窗口按钮、菜单按钮、菜单项各 120ms；代码块工具条 150ms。
- 2 个 keyframes 都只服务命令面板：遮罩 `mdv-fade` 140ms、面板 `mdv-pop` 160ms；两者同时开始，感知约 160ms。
- F2、目录、标签条、主题四处切换是 0ms；菜单弹出也是 0ms——后者是对的，不要补。
- `prefers-reduced-motion` 块只写了 `transition: none` 和 `scroll-behavior: auto`，`animation` 未覆盖；全项目唯一的动画恰好在这个漏洞里。
- 每个代码块右上角有一个 `opacity: 0` 的工具条，仍接收指针和焦点；Tab 会停在一个看不见的“复制”按钮上。
- 目录开关是 220px 的硬切：正文重排，`scrollTop` 不变，阅读位置会漂。

**如果只做一件事**：MO-02，把 `animation` 纳入 `prefers-reduced-motion`。一行 CSS、A 级、零视觉风险，补的是规格已经写明、实现只差半句的硬要求。如果还愿意多花半天，再做 MO-01 的目录锚点。

## 1. 判定口径

| 原则 | 在本项目里的含义 | 不达标时用户会怎样 |
|---|---|---|
| **反馈优先** | 每次状态改变都要有可感知的回应；阅读工具的 120ms 足够，不需要“演出” | 不知道操作有没有生效，重复点击或放慢节奏 |
| **高频短、低频可长** | F2、目录、切标签是高频，≤120ms 或 0ms；首次出现、面板打开可到 160ms | 高频动作一慢就烦；低频动作太快又没感觉 |
| **只动合成属性** | 优先 `opacity`、`transform`、`background-color`、`color`；不动 `width/height/flex-basis/filter` | 2.3MB 文档和 3955 条目录上滚动掉帧 |
| **位置稳定** | 动效不能把用户正在读的那一行移走；布局变化后要回到同一个内容锚点 | 开个目录就找不到刚才读到哪 |
| **可关闭** | 尊重 `prefers-reduced-motion: reduce`；关掉动画后信息仍然完整 | 晕动用户无法使用；动画成了唯一状态信号 |
| **不表演** | 不做装饰性循环、不做成功庆祝、不做骨架屏闪光 | 注意力从文字被拉回界面 |
| **不给高频内容加交叉淡化** | 编辑层和阅读层是同一段文字的两个表示，不是两张幻灯片 | 两段文字叠在一起，反而更晕、更慢 |

**与既有规格的关系**：`specs/00` 的外壳动效表写的是「hover 120ms / 切换 160ms / toast 180ms」，并要求 `prefers-reduced-motion` 全局尊重。本文件的 M-01～M-07 都在这个口径内；只有 M-04（F2 豁免）和 M-08（toast 是否保留）需要改口径。

## 3. P1 · 高影响

### MO-01 目录开关是 220px 的硬切，正文重排后阅读位置会漂

**现象**：`#toc` 是 `flex: 0 0 220px` 的侧栏；`setTocVisible` 直接把 `hidden` 置为 `!manual`，阅读区 `flex: 1` 立刻从“窄栏”变“宽栏”。没有任何过渡，也没有在切换前后补偿滚动位置。`scrollTop` 保留的是像素值，但正文宽度变了、行高和换行都变了，同一个 `scrollTop` 对应的段落已经不是原来那段。

**证据**：`app.css::#toc`（`flex: 0 0 220px`）；`app.css::#stack > #editor-host, #stack > #reader`（`flex: 1`）；`toc.js::setTocVisible`（`el.hidden = !manual`）；`app.js::MDV.toggleToc`；`reader.js::currentSection`

**原则**：位置稳定

**影响**：用户读到一半按 Ctrl+Shift+O，正文栏变宽，正在读的那一段跳走；再按一次，它也不会精确回到原处，因为切回去的 `scrollTop` 是“上次的像素值”，不是“上次的内容锚点”。对一本 2.3MB、几千个标题的书，这种漂移每次开合都会发生。读者会养成“不敢动目录”的习惯，目录反而成了干扰。

**改法**：
1. 切换前记录 `MDV.currentSection()` 的 `chapterId`（或 `volumeId`），以及当前视口顶部第一个标题的 `getBoundingClientRect().top` 偏移。
2. 切换后在 `requestAnimationFrame` 里调用 `MDV.scrollToHeading(id)`，再按记录的偏移修正；目标是把同一段文字保持在视口同一高度（±24px）。
3. 可选：给 `#toc-list` 做 120ms `opacity` 淡入，**不要**给 `width` / `flex-basis` 做过渡——那会让阅读区每一帧重排。

**规格影响**：无（纯行为修正，不动视觉口径）

**验收问题**：在 50% 位置开/关目录各一次，视口顶部那段文字是否保持在 ±24px 内？

## 4. P2 · 中等影响

### MO-02 `prefers-reduced-motion` 只关了 transition，没关 animation

**现象**：`@media (prefers-reduced-motion: reduce)` 里只有 `* { scroll-behavior: auto !important; transition: none !important; }`。全项目唯一的两个 `animation`（`#palette` 的 `mdv-fade`、`#palette-box` 的 `mdv-pop`）不受影响，所以在“减少动效”模式下打开命令面板，仍然会看到 140ms 淡入 + 160ms 上移缩放。规格要求的是“全局尊重”，实现只覆盖了 `transition` 这一半。

**证据**：`app.css::@media (prefers-reduced-motion: reduce)`；`app.css::#palette`（`animation: mdv-fade 140ms`）；`app.css::#palette-box`（`animation: mdv-pop 160ms`）；`specs/00::该做与不该做`（`prefers-reduced-motion` 全局尊重）

**原则**：可关闭

**影响**：设置了“减少动效”的用户，打开唯一一个带动画的面板时仍会被弹一下。因为全项目只有这一处动画，这个漏洞等于 100% 的动画都没被尊重。它不影响完成任务，但这是规格明确承诺过的可访问性开关，不能算“可选项”。

**改法**：
1. 在现有块里补 `animation: none !important;`。
2. 再补 `animation-duration: .01ms !important;` 作为兜底（防止未来某个动画用内联样式覆盖 `animation: none`）。
3. 保留 `transition: none !important`；颜色/悬停过渡在 `reduce` 下也可以关，信息不会丢。

**规格影响**：无（补规格已要求的行为）

**验收问题**：DevTools 模拟 `prefers-reduced-motion: reduce` 后打开命令面板，是否完全没有位移/淡入？

### MO-03 代码块工具条透明但仍可点、可聚焦，Tab 会停在看不见的“复制”上

**现象**：`.code-bar` 默认 `opacity: 0`，绝对定位在每个代码块右上角，只有 `.code-wrap:hover` 才把透明度拉到 1。它没有 `pointer-events: none`，也没有 `:focus-within` 规则；里面的 `.code-copy` 是真正的 `<button>`，所以键盘 Tab 会停在它上面，但视觉上仍是透明的。鼠标在代码块右上角按下时，也可能先命中这块透明区域。

**证据**：`app.css::.md-body .code-bar`（`opacity: 0`、`position: absolute`、`top/right`）；`app.css::.md-body .code-wrap:hover .code-bar`（只有 hover 显形）；`reader.js::enhanceCodeBlocks`（创建 `button.code-copy`）

**原则**：可关闭 / 反馈优先（延伸为“可键盘看见”）

**影响**：键盘用户按 Tab 穿过代码块时，焦点会消失在一个看不见的按钮上，不知道当前会复制什么；鼠标用户想选代码右上角时，可能先触发复制。代码块在技术文档里密度很高，这不是边角场景。透明度本来是为了“不打扰阅读”，但透明不等于不可交互。

**改法**：
1. 补 `.code-wrap:focus-within .code-bar { opacity: 1; }`，让键盘焦点进入时整条显形。
2. 默认 `pointer-events: none`；在 `:hover` 和 `:focus-within` 下改回 `auto`。`pointer-events` 不影响键盘聚焦，所以 Tab 仍然能进入并触发显形。
3. 时长从 150ms 收到 120ms，和其余悬停一致；只动 `opacity`，不动布局。

**规格影响**：无（纯实现）

**验收问题**：只用键盘 Tab 到代码块，工具条是否在焦点到达前显形？鼠标在右上角拖选是否不会误触复制？

---

### MO-04 F2 与标签条都是 0ms，而规格写的是「切换 160ms」；要按面分别决定

**现象**：`specs/00` 的动效表写「hover 120ms / 切换 160ms / toast 180ms」。实际 `setMode` 用 `hidden` 直接换层，0ms；`setTabs` 切换 `tabbar.hidden`，0ms。F2 的双态切换是高频内容替换（项目记录带重渲约 93ms），标签条首次出现是 36px 的布局变化。两者被同一句“切换 160ms”覆盖，但正确的处理方向相反。

**证据**：`specs/00::应用外壳视觉法`（动效表）；`app.js::setMode`；`app.js::MDV.setTabs`；`app.css::#tabbar`；`TODO.md::性能复测`（F2 带重渲 93ms）

**原则**：高频短、低频可长 / 不给高频内容加交叉淡化

**影响**：如果按字面给 F2 加 160ms 交叉淡化，编辑层和阅读层会短暂叠字，反而更难读，也把 93ms 的重渲拖到 250ms 以上；如果继续 0ms，规格又一直对不上。标签条则相反：第一次出现时正文被向下推 36px，0ms 会让这次变化显得“闪了一下”。这不是“缺动画”，是“规格没区分两类切换”。

**改法**：
1. 在 `specs/00` 的动效表里补一句：**内容双态切换（F2）豁免过渡，0ms**；理由是同一段文字的两个表示，不是两个视图。
2. 标签条首次出现做 120ms `opacity` + `translateY(-4px)`，只动标签条自身，不动 `height`，避免阅读区二次重排。
3. 编辑层/阅读层容器保持 0ms；不要给 `#reader` / `#editor-host` 加 `transition`。

**规格影响**：**需确认**（修改动效口径表）

**验收问题**：F2 是否仍然“按下即到”（没有两段文字重叠），标签条出现是否不再硬闪？

## 5. P3 · 一致性与细节

### MO-05 命令面板打开有 160ms，关闭是 0ms

**现象**：打开时 `#palette` 淡入 140ms、`#palette-box` 上移缩放 160ms，两条同时开始；关闭时 `closePalette` 直接 `hidden = true`，`#palette[hidden] { display: none; }` 立即切断，没有退出过渡。

**证据**：`app.css::#palette` / `#palette-box`；`app.css::#palette[hidden]`；`app.js::closePalette`

**原则**：一致

**影响**：打开“软”，Esc 关闭“啪”一下。命令面板是高频工具，关闭通常比打开更急；这种不对称会让面板显得“进来很隆重，出去很敷衍”。但它不影响完成，所以是 P3。

**改法**：二选一。1）去掉打开动画，像菜单一样瞬间出现、瞬间关闭；2）保留打开，补 90ms `opacity` 的 `.closing`，`transitionend` 后 `hidden = true`，200ms `setTimeout` 兜底。推荐 2，因为现有打开动画已经写好了。

**规格影响**：无

**验收问题**：连续开/关 10 次，是否不再有“进去慢、出来快”的割裂感？

---

### MO-06 主题切换是全屏 0ms 颜色跳变，规格却写了 160ms

**现象**：`MDV.setTheme` 逐条 `setProperty` 改变量；`.md-body`、`body`、代码块、表格这些大面积颜色没有 `transition`，所以切主题是一次全屏亮度跳变。只有 TOC 项、菜单按钮等少数外壳组件有 120ms 颜色过渡，内容区没有。

**证据**：`app.js::MDV.setTheme`；`app.css::.md-body`、`app.css::body`；`specs/00::动效`（切换 160ms）

**原则**：一致 / 不表演

**影响**：从 paper 切到 midnight 是一次整屏由亮到暗的跳变，夜里尤其刺眼。但给每个元素加颜色过渡会在 2.3MB 文档上引发大面积重绘，得不偿失。这是“规格写了但实现没做，而且不该照字面做”的典型。

**改法**：
1. **不要**给 `.md-body *` 加 `transition: background-color/color`。
2. 如果要柔化，用一个覆盖全屏的固定遮罩：切换前记录旧 `--bg`，遮罩从旧色 160ms 淡出到透明；只动一个 `opacity` 图层。
3. 或者直接在 `specs/00` 里把“主题切换”标为豁免，保持 0ms。

**规格影响**：**需确认**（改口径或加一个遮罩层）

**验收问题**：切主题时是否没有白闪、没有长帧，且要么瞬间到位、要么只看到一个整体淡出？

---

### MO-07 时长有 120 / 140 / 150 / 160 四档，而口径表只有三个角色

**现象**：TOC、窗口按钮、菜单按钮、菜单项都是 120ms；代码块工具条 150ms；面板遮罩 140ms；面板本体 160ms。`specs/00` 只定义了 hover 120ms / 切换 160ms / toast 180ms，140 和 150 不在表里。

**证据**：`app.css::.toc-item`、`.win-btn`、`.menu-btn`、`.menu-item`（120ms）；`.code-bar`（150ms）；`#palette`（140ms）；`#palette-box`（160ms）；`specs/00::动效`

**原则**：一致

**影响**：单看每一处都不明显，但新增动效时会随手抄一个“附近的值”，档位会继续发散。用户说不清哪里不齐，只会觉得“有些地方软、有些地方硬”。

**改法**：
1. 在 `app.css :root` 建三个 token：`--mo-hover: 120ms`、`--mo-switch: 160ms`、`--mo-toast: 180ms`。
2. 代码块工具条 150 → 120（它是悬停反馈）；面板遮罩 140 → 160 或 120，与面板本体统一。
3. 以后只允许引用 token，不写 `0.15s` / `140ms` 字面量。

**规格影响**：无

**验收问题**：`app.css` 里除 token 定义外，是否不再出现时长字面量？

---

### MO-08 同样是“选中”，TOC 有 120ms，标签没有

**现象**：`.toc-item` 有 `background/color 120ms`，切换章节时高亮是渐变的；`.tab.active` 直接换背景，没有 `transition`；`.menu-item.checked` 的颜色会走 `.menu-item` 的 120ms，但字重是瞬时跳的。三个“当前项”三种手感。

**证据**：`app.css::.toc-item`；`app.css::.tab.active`；`app.css::.menu-item.checked`

**原则**：一致

**影响**：切标签时背景“啪”地跳，切目录时慢慢染过去；同一屏里两种选中语言。菜单保持瞬时是对的（菜单要高快），但标签和 TOC 都是常驻导航，应该同一种手感。

**改法**：给 `.tab` 补 `transition: background 120ms ease, color 120ms ease`；菜单保持 0ms，不补。只动颜色，不动宽度/边框。

**规格影响**：无

**验收问题**：连续切标签和连续点目录，选中反馈是否像同一套控件？

---

### MO-09 所有按钮只有 hover，没有按下态

**现象**：`.win-btn`、`.menu-btn`、`.code-copy`、`.pal-item` 都只定义了 `:hover`，没有 `:active`；按下时背景不变化，只有动作完成后的结果。

**证据**：`app.css::.win-btn`、`.menu-btn`、`.md-body .code-copy`、`.pal-item`

**原则**：反馈优先

**影响**：桌面应用里，按下窗口按钮/复制按钮时没有任何“按到了”的视觉确认，只有结果。对大多数操作来说结果本身就是反馈，所以这是 P3；但代码复制这种没有跳转的动作，按下态能减少“我是不是没点到”的犹豫。

**改法**：加一条统一的 `:active { background: var(--shell-selected); }`，0ms，不做缩放/位移动画。菜单项可以不加（菜单点击即关闭，结果足够）。

**规格影响**：无

**验收问题**：按住代码块的“复制”按钮不放，是否能看到按下态，且松手后才执行复制？

---

### MO-10 规格里的「toast 180ms」没有对应的 toast

**现象**：页面侧只发 `toast` 事件（例如“文档过大，暂不支持编辑”），`main.pyw` 把它转给 `statusbar.set_temp`，最终是状态栏文字替换，2 秒后换回。没有浮层 toast，也没有 180ms 的进入/退出；`specs/00` 的 180ms 目前没有 owner。

**证据**：`specs/00::动效`（toast 180ms）；`main.pyw::_on_web_event`（`toast` 分支）；`statusbar.py::set_temp`；`app.js::MDV.setStatusTemp`

**原则**：一致 / 不表演

**影响**：规格里有一个时长，代码里没有这个组件；未来有人按表实现 toast，会多出一个和状态栏重复的通知通道。对“界面被遗忘”的产品，浮层 toast 未必是好事——状态栏一行字更安静。

**改法**：二选一。1）把规格改成「状态栏临时消息 120ms opacity，无浮层 toast」；2）真做 toast 时，用底部居中、`opacity` 180ms、2 秒自动消失，并去掉状态栏的同名提示。推荐 1。

**规格影响**：**需确认**（改口径或新增组件）

**验收问题**：规格里的“toast”和实现里的“临时消息”是否指同一个东西、同一个时长？

## 7. 禁止清单（不要加）

| 不要加 | 为什么 |
|---|---|
| **F2 编辑/阅读交叉淡化** | 同一段文字的两个表示，叠在一起会短暂“双影”；还会把 93ms 的重渲拖到 250ms 以上。保持 0ms |
| **目录 `width` / `flex-basis` 过渡** | `#toc` 是 flex 子项，宽度动画会让阅读区每一帧重排；2.3MB 文档上必掉帧。只淡入内容，不动宽度 |
| **标签条 `height` 过渡** | 高度变化同样会推动阅读区；用 `opacity + translateY`，不要动 `height` |
| **菜单弹出 160ms 淡入** | 菜单是高频定位工具，桌面惯例是瞬时；延迟会让人觉得“卡”。当前 0ms 是对的 |
| **主题切换给每个元素加颜色过渡** | 几千个节点同时变色，重绘成本高，且可能出现半旧半新的中间态。要柔化只用一层遮罩 |
| **阅读区滚动视差 / 随滚动缩放** | 直接和阅读、分块渲染抢滚动；晕动风险最高 |
| **分块占位块的 skeleton shimmer** | 占位块已经用估算高度撑住滚动范围；闪光会把注意力吸引到“还没渲染”，而不是“已经读到” |
| **章节跳转的翻页/滑动动画** | 这是阅读器，不是幻灯片；跳章要的是“立刻到”，不是“翻过去” |
| **无限循环的加载指示** | 分块渲染是确定性的短任务；没有长时间等待，不需要 spinner，更不需要循环脉冲 |
| **复制成功的弹跳/彩带/音效** | 一次阅读会复制很多次；文字「已复制」已经足够，庆祝会变成噪音 |
| **给 `#reader` / `#editor-host` 加 `filter` / `blur` 过渡** | 大面积滤镜在 WebView2 上很贵，且会让文字发虚；阅读工具不应该动内容层的滤镜 |

## 8. 工程约定（写实现文档时直接抄）

1. **时长只有三档**：`--mo-hover: 120ms`、`--mo-switch: 160ms`、`--mo-toast: 180ms`。不新增 140/150/200ms；不在局部写 `0.15s` 之类的字面量。
2. **曲线**：悬停/选中用 `ease`，进入用 `ease-out`，退出用 `ease-in`。不手写 spring——项目没有动画框架，手写容易抖。
3. **只动这些属性**：`opacity`、`transform`、`background-color`、`color`、`border-color`。不动 `width`、`height`、`flex-basis`、`top/left`、`filter`、`blur`。
4. **内容层豁免**：`#reader`、`#editor-host`、`.md-body` 不做过渡；动效只加在外壳（菜单、标签条、TOC、面板、代码工具条）。
5. **`prefers-reduced-motion` 一次写全**：`transition: none !important; animation: none !important; animation-duration: .01ms !important; scroll-behavior: auto !important;`。
6. **`hidden` 会切断过渡**：需要退出动画时，用 `.closing` 类 → `transitionend` → `hidden = true`，并加 200ms `setTimeout` 兜底；不需要退出动画的（菜单、F2）就保持瞬时，不要硬加。
7. **首帧不播放**：新元素插入后先渲染一帧（`requestAnimationFrame`），再加 `.visible` / `.open` 类；或用 `data-shown` 标记，保证重渲染不重播。
8. **布局变化先保锚点**：任何会改变阅读区宽度的操作（目录开关、窗口缩放、字体切换），先记录当前标题 id + 视口偏移，变更后用 `scrollToHeading` 修正。
9. **不在滚动路径上读布局**：动效代码不要每帧 `getBoundingClientRect`；需要时先缓存，或用 `requestAnimationFrame` 合并。
10. **动效不能是唯一信号**：关掉动画后，当前标签、当前目录项、已复制、保存失败仍然要看得出来。
11. **在 100% 与 150% 缩放下各看一次**：位移和描边在 150% 下会放大，需确认不糊、不抖。
12. **在 2.3MB 文档上验证**：项目记录的最大书是 2.3MB / 3955 个标题；任何新增动效都要在这个规模下开一次目录、切一次 F2、开一次面板。

## 9. 已经做对的部分（改的时候不要一起动）

- **动效基线克制**：全项目 5 条 transition、2 个 keyframes、0 个 `infinite`；没有装饰性循环，也没有和内容抢注意力的动画。这是阅读工具的正确方向。
- **两个 keyframes 都只用 `opacity` 和 `transform`**，没有动布局属性；命令面板的弹出是合成层动画，成本低。
- **菜单弹出保持 0ms**：这是桌面惯例，不要因为“规格写了 160ms”就给它补淡入。
- **`.code-bar` 只用 `opacity`**，没有动代码块高度；方向是对的，只差焦点显形和指针穿透（MO-03）。
- **TOC 选中高亮有 120ms 过渡**，滚动跟随时不会“跳色”；这是全项目最舒服的一处状态反馈。
- **`prefers-reduced-motion` 块已经存在**，且关掉了所有 `transition`；补一行 `animation` 就能完整（MO-02）。
- **F2 保持 0ms 是正确的**：项目记录的重渲约 93ms，再加交叉淡化只会更慢；不要为了“统一”牺牲它。
- **章间跳转/TOC 跳转是 `scrollTop` 直接赋值**，没有平滑滚动；对长文档这是对的，平滑滚动会让人等。
- **状态栏临时消息有 2 秒超时和恢复逻辑**，不会永久占位；问题在“抢占基础信息”（AUDIT-01 IA-08），不在超时机制。

## 11. 验证方法（不跑测试也能验的版本）

1. **Reduced motion**：DevTools → Rendering → Emulate CSS `prefers-reduced-motion: reduce`，打开命令面板，确认没有 `mdv-fade` / `mdv-pop`；再确认 TOC 悬停、菜单悬停仍然可用（信息不丢）。
2. **代码工具条键盘路径**：只用 Tab 走到代码块，确认工具条在焦点到达时显形；再用鼠标在代码右上角拖选，确认不会误触“复制”。
3. **目录锚点**：打开 2.3MB 的《鬼探实录》，滚到 50%，记录视口顶部第一行；按 Ctrl+Shift+O 开、再关，比较同一行是否仍在 ±24px 内。
4. **帧数**：用系统录屏 60fps 录 10 次命令面板打开/关闭，0.25× 回放数帧；160ms 约 10 帧，90ms 约 5 帧。目标是不出现 >200ms 的空白或跳变。
5. **Performance 面板**：录“开/关目录”“F2 往返”“开面板”，看 Layout / Paint 是否出现 >50ms 的长任务；加动效前后各录一次，目标是**不比现在差**。
6. **Paint flashing**：Rendering → Paint flashing，确认动效只重绘小区域；若整屏闪绿，说明动了布局属性。
7. **150% 缩放**：Windows 显示设置调到 150%，重看代码工具条、TOC 淡入、标签条位移是否发虚或错位。
8. **四套主题**：paper / midnight / forest / pure 各切一次，确认没有白闪、没有半旧半新的中间态；深色下确认 `--shell-scrim` 和面板阴影仍然够。
