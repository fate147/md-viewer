# 规格 10 · 多格式文件查看

> 类型：主规格（系统当前必须遵守的规则）｜建立：2026-11-24｜来源：用户需求「不只显示 MD，EXE/PDF/其他类型也想用它打开」

## 适用范围
打开**非 `.md`** 文件时的类型判定、渲染、编辑与写盘护栏、桥字段。覆盖 `src/core/filetypes.py`、`src/actions.py`、`src/ui/web_client.py`、`src/assets/app.js`、`src/assets/reader.js`、`src/assets/app.css`。

## 必须遵守的规则

**R-10-01【类型判定】** 唯一实现 `core/filetypes.py` `detect()`，返回 `markdown | text | image | pdf | ebook | html | binary`：
- 扩展名优先：图片扩展（`.png/.jpg/.jpeg/.gif/.webp/.bmp/.svg/.ico`）→ `image`；`.pdf` → `pdf`；`.epub/.mobi/.azw3/.azw/.rtf/.odt/.fb2` → `ebook`；`.html/.htm/.xhtml` → `html`；`.md/.markdown/.mdown` → `markdown`。
- 其余嗅探**前 8KB**：含 `NUL` 或控制字符占比 > 10% → `binary`；否则按 `utf-8-sig → utf-8 → gbk` **严格解码**（先去掉尾部 4 字节，规避截断在多字节字符中间）；仍失败时用 `replace` 解码，坏字符（U+FFFD）占比 ≤ 5% 仍判 `text`；否则 `binary`。
- 只读文件头，**禁止**在判定阶段读全文；正文读取仍归 `core/fileio.py`。头部可解码但整篇解码失败时，调用方降级为 `binary` 而不是报错弹窗。

**R-10-02【text 渲染】** 走 `MDV.renderPlain`：
- 按行边界切成 ≤ `BLOCK_MAX_RAW`（4000 字符）的块，**复用**分块的占位/前缀和/分段/滚动渲染机制（含 `SEG_MAX_PX` 分段，超长 `.txt` 也能滚到底）。
- 每块输出 `<pre class="plain-text">` + HTML 转义，保留原始换行；**禁止**跑 marked 解析（源码注释里的 `#` 不得变成标题）。
- 排版：纯文本**按正文排版**，必须压掉 `.md-body pre` 的代码块外框（背景/边框/圆角/内边距一律清零，`app.css` 用 `#reader pre.plain-text` 提权）；`.txt/.log` 等正文用正文字体，`.py/.json` 等代码类加 `.mono` 用等宽。用户口径：「不要把它框在那个框里面，正常显示就可以」。
- 大纲仍由 `buildOutline` 从块 raw 逐行识别卷/章（与 markdown 同源），目录可用于长篇小说。
- 纯文本块**不得**执行 `decorateBlock` / `enhanceBlock`（否则每个块挂代码复制按钮）。

**R-10-03【image 渲染】** 只读视图：`#reader` 内挂 `.img-view > img`（`src` 为 `file_url()` 生成的 file URL），按容器宽度等比缩放。不建编辑态、不生成大纲、不计字数。

**R-10-07【pdf 渲染】** iframe 交给 WebView2 内置 PDF 查看器：
- `#reader` 内挂 `.pdf-view > iframe.pdf-frame`，`src` 为 `file_url()`；容器绝对定位铺满阅读区（`#reader` 已设 `position: relative`）。
- 页面本身是 `file://`，iframe 直接加载 `file://` PDF **实测可用**（2026-11-24 截图验证：工具栏/页码/正文齐全），**不得**为此引入虚拟主机映射或第二个 WebView2 控件（如后续版本失效再单独评估）。
- 只读：不建编辑态、无大纲、隐藏目录侧栏；**禁止**保存/导出/朗读。

**R-10-08【ebook 渲染】** `.epub/.mobi/.azw3/.azw/.rtf/.odt/.fb2` 由 Python 侧抽取成 Markdown 再进阅读层：
- 唯一实现 `core/ebook.py` `extract()`，按扩展名分派 `extract_epub` / `extract_mobi` / `extract_rtf` / `extract_odt` / `extract_fb2`；页面**不得**自己解析电子书格式。
- 输出形如 `# 书名` + 各章 `## 章节名`，因此目录、分块、分段、滚动全部复用文本管线（`kind=ebook` 与 `markdown` 同一渲染路径）。
- 只读：`kind=ebook` 不在 `is_text_like` 内，编辑/保存/自动保存/导出/朗读/复制全部拦（R-10-05）。
- 抽取失败**必须**落信息卡并给出具体原因（`note` 字段经 `openDoc` meta 下发）：DRM 加密、HUFF/CDIC 压缩、纯 KF8 的 AZW3、文件损坏。**禁止**静默显示空页。
- v1 不做：内嵌图片、原书排版/CSS、脚注跳转、Kindle DRM 解密。

**R-10-09【html 渲染】** `.html/.htm/.xhtml` 用 `#reader` 内 `.html-view > iframe.html-frame` 直接渲染（同 R-10-07 的 file:// 方案），只读、无大纲、隐藏目录侧栏。

**R-10-04【binary 不渲染】** 挂 `.bin-view` 信息卡：文件名 + 文件大小 + 「用系统默认程序打开」按钮；按钮经上行事件 `openExternal(path)` 交给 `main.pyw` `_open_external`（`os.startfile`）。**禁止**尝试把二进制内容塞进编辑器或阅读层。

**R-10-05【编辑与写盘护栏】** 只有 `markdown` / `text` 允许编辑与写盘：
- 编辑入口三处同门：`enterEditor()`、`MDV.toggleMode()`、`MDV.insertText()`；非文本类型提示「该文件类型不支持编辑」并保持阅读态。
- 写盘/导出/朗读/复制入口：`actions.save`、`actions.save_as`、`actions.export_html`、`main.pyw._auto_save`、`main.pyw.copy_as_plain_text`、`actions.speak`，一律先判 `filetypes.is_text_like(kind)` 再继续。
- **禁止**对 image/binary 走 save/auto-save：空文本落盘会直接清空文件。

**R-10-06【桥字段】** 装载头 `openDoc(id, meta)` 的 `meta` 必须携带 `kind` / `src` / `path` / `size`（见 05 R-05-13）；内容分块、`_CHUNK`、就绪门、超时重发沿用 05，不得为多格式另开通道。

## 禁止事项
- 禁止对 `image` / `binary` 建 `EditorState`。
- 禁止非文本类型写盘（见 R-10-05）。
- 禁止在 `app.js` / `actions.py` 各自实现一套扩展名判断（唯一源 `core/filetypes.py`）。
- 禁止为多格式引入新的桥通道或新页面（延续 05 R-05-09）。

## 与其它规格的依赖
- 依赖 **05-桥协议**（`openDoc` meta、`openExternal` 事件、分块与就绪门）。
- 依赖 **03**（分块/分段/大纲机制，R-10-02 直接复用）。
- 被 **02-文件与标签生命周期** 依赖（`TabState.kind`）。
