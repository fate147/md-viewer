# 规格 02 · 文件与标签生命周期

> 类型：主规格（系统当前必须遵守的规则）｜建立：2026-10-26｜更新：2026-10-26（按确认骨架对齐 + 补 R-02-06/R6）｜来源：排查报告《功能地图与风险点排查.md》

## 适用范围
标签新建/切换/关闭/退出、core/session.py、actions.py、app.js 标签条、core/fileio.py（文件 I/O）。

## 必须遵守的规则

**R-02-01【宪法级 · 跨语言主键 方案 A】** Python 维护单调递增整型 `tab_seq` 作为唯一跨语言主键（`tab_seq` 只增不减、不复用）；`id(tab)` 仅作 Python 内部字典键；桥上所有标签标识符一律传 `tab_seq`（不存在名为 `tab_id` 的独立概念；历史代码若有 `tab_id` 参数，其值必须等于 `tab_seq`）；JS `state.docs` 的键即 `tab_seq`。禁止任何桥消息出现 `id(tab)`。
**唯一键出口**：Python 业务代码取标签的跨语言标识一律经 `core.session.tab_key(tab)`；禁止直接写 `id(tab)` 或 `tab.seq`——切换主键实现只改 `tab_key()` 一处，保证两侧键空间原子切换、不出现半套键。**仓库根测试脚本（`smoke_app.py`、`test_bridge_integration.py`）同样适用，不得例外**——它们直接调用 `web.request_text` / `select_tab_by_id` / `close_tab_by_id`，键不对会静默取错标签。
**分配规则**：`tab_seq` 由 `Session` 分配（`Session._next_seq` 自增，`TabState.seq` 持有，`0` 表示未分配）；`open_tab`（`session.py:66`）与 `add_untitled`（`session.py:73`）是唯一分配点；标签关闭后其 `seq` 作废且永不复用。
- 依据：排查报告 R2；`main.pyw:42,181,288`、`actions.py:32,33,35,49,50,100,110,120,133,153,164,170,200`、`app.js:21`、`session.py:15-23,66,73`
- **迁移状态**：第一步已完成（2026-10-26）——19 处 `id(...)` 全部收口为 `tab_key(...)`，`tab_key()` 实现暂为 `return id(tab)`，行为与改前等价。第二步待拍板：`tab_key()` 改为 `return tab.seq`，并同步修正 R-02-02 的关闭时序。
- **测试脚本同步（2026-10-26）**：`smoke_app.py:48`、`perf_baseline.py:101`、`test_bridge_integration.py:78,114,117,122,125,130` 共 **8 处** `id(...)` 已收口为 `tab_key(...)`。此前它们与业务代码共用 `id()`，第二步切换后会取到错误键（当前只是碰巧相等），故与第一步同批收口（`perf_baseline.py` 那处是第二轮补扫发现的，首轮漏计）。

**R-02-02【双源真相对齐 · 关闭时序】** `_loaded`（Python）与 `state.docs`（JS）必须由 `tab_seq` 对齐，关闭标签严格执行以下顺序，**禁止颠倒**：
① Python 记下要关闭的 `tab_seq`；
② 发关闭通知令 JS 删除 `state.docs[tab_seq]` 并清理缓冲（JS 侧删除见 `app.js:219` 对账 delete、`app.js:241,245` closeTab 事件）；
③ Python 确认 JS 已清理后，再 `_loaded.discard(tab_seq)` 并从 session 移除该标签。
**禁止先 `discard` 再通知 JS**——否则 JS 侧 `state.docs` 仍持有旧缓冲，后续 `setTabs`（`app.js:214-220`）对账因错配导致标签内容变空；新建标签前必须完成上述三步。
- 依据：排查报告 R1-②、R2；`web_client.py:182`（set_tabs）、`:195`（send_text）、`app.js:214-220,219,241,245`、`actions.py:164`（`_loaded.discard`）
- **迁移状态**：**当前代码顺序待修正**——`actions.py:163`（`sess.close_tab`）→ `:164`（`_loaded.discard`）→ `:166`（经 `_after_tab_switch`→`refresh_all`→`setTabs` 才通知 JS），即先 `discard` 后通知，违反本条①②③；修正并入第二步（与 `tab_key` 热切换同批）。

**R-02-03** `setTabs` 对账以 `tab_seq` 为准，不得以顺序/标题推断身份。
- 依据：`app.js:214-220`

**R-02-04** 死字段 `cursor`/`title`/`mark_dirty`（`session.py:22,30-32,93-94`）禁止被新代码读取；删除放到执行阶段。
- 依据：排查报告 R3；`session.py:22,30-32,93-94`

**R-02-05** `session.py` docstring 必须与真实缓冲位置一致（缓冲在浏览器 `state.docs`）。
- 依据：排查报告 D1；`session.py:4-6`
- **迁移状态**：已消除（2026-10-26 已同步：`session.py:5,23` 改为浏览器 `state.docs`）

**R-02-06【R6 · 编码回写不得丢 BOM】** 文件保存必须经 `core.fileio.write`；编码探测顺序固定 `ENCODINGS`（`utf-8-sig → utf-8 → gbk`，`fileio.py:15,18,37`）。保存时必须沿用读取时探测到的编码（`tab.encoding`）：原文件为 `utf-8-sig` 的，回写必须保留 BOM；禁止在 `actions.py:74` 的「另存为」分支里无差别强制 `utf-8`。编码探测失败时禁止静默写盘——必须报错并由用户决定，防止丢数据/损坏文件。
- 依据：排查报告 R6；`fileio.py:18,37`、`actions.py:74`
- 违反后果：`utf-8-sig` 文件被改写丢失 BOM；探测失败直接损坏/丢数据。

**R-02-07** 保存/关闭/退出一律走“确认 → `request_text` 拉全文 → 写盘 → 下一步”异步链；禁止 Python 侧直接持有文本做同步写。
- 依据：排查报告 R7；`actions.py:54-61,103-110,137-156,175-200`

**R-02-08** 会话恢复只读 `open_tabs` 路径、按需装载不读内容、**上限 8 个**（`main.pyw:107` 的 `s.get("open_tabs", [])[:8]` 硬约束）；未保存标签关闭/退出必须弹确认，文本取回失败（`None`）宁可不动、不丢内容。
- 依据：`main.pyw:92-113`（其中 `:107` 的切片 `[:8]` 即「上限 8 个」约束）；`session.py:98-110`；`actions.py:137-200`
- **单一真相**：`session` 恢复上限（8）在本规格定义，06 R-06-06 只引用、不重复；`recent_files` 规则（上限 10/去重）以 **06 R-06-05** 为唯一源，本规格只引用、不重复其数字。

## 禁止事项
- 禁止用 `id()` 作跨语言主键（R-02-01）。
- 禁止关闭标签后不通知 JS 清理、不校验 `tab_seq` 唯一就新建（R-02-02）。
- 禁止 Python 缓存/持有标签文本（R-02-07）。
- 禁止读取死字段 `cursor/title/mark_dirty`（R-02-04）。
- 禁止保存时丢失原文件 BOM、禁止「另存为」无差别强制 `utf-8`（R-02-06）。
- 禁止编码探测失败静默写盘（R-02-06）。
- 禁止 `session` 持久化写入文本（R-02-08）。
- 禁止 JS / Python 任一侧单独删除标签缓冲（须经 `setTabs` 对账）。

## 与其它规格的依赖
- 依赖 **05-桥协议**（`request_text`/`set_tabs`/`send_text` 主键契约）。
- 依赖 **06-配置与持久化**（`recent_files` 规则以 06 R-06-05 为源；`session` 上限在本规格 R-02-08 定义，06 只引用）。
- 被 **03-编辑⇄阅读双态与排版** 依赖（标签切换时联动缓冲）。
